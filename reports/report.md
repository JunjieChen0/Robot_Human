# 人机交互课程作业 1：手机活动识别模型训练与交互评价

> 本报告中的模型数据来自实际运行结果；用户测试部分必须在邀请至少 3 名同学完成测试后填写，不能使用虚构数据。

## 1. 研究背景与作业目标

本项目使用手机惯性传感器数据识别用户在短时间窗口内的日常活动，完成从数据处理、模型训练、测试集评价到交互原型设计的完整流程。项目重点不只是比较模型分数，还关注预测结果是否容易理解、不确定性是否被正确表达，以及用户能否完成输入、查看结果、修改和重新预测。

本项目只用于课程学习。模型结果不作为医学诊断、疾病筛查或治疗建议。

## 2. 任务定义、目标用户与使用场景

### 2.1 任务

输入一个约 2.56 秒的手机传感器窗口，输出以下六类活动之一：行走、上楼、下楼、坐姿、站姿和卧姿。

### 2.2 目标用户

普通大学生、健身者和健康管理用户。

### 2.3 使用场景

用户在网页原型中选择活动样例或上传一行特征 CSV，查看预测活动和各类别概率，再修改特征并重新预测。

## 3. 数据来源与数据说明

数据集为 UCI Human Activity Recognition Using Smartphones：

- 数据集主页：https://archive.ics.uci.edu/dataset/240/human+activity+recognition+using+smartphones
- DOI：https://doi.org/10.24432/C54S4K
- 受试者：30 名匿名志愿者；
- 活动窗口：10,299 条；
- 采样频率：50 Hz；
- 每个窗口：128 个采样点，约 2.56 秒；
- 传感器：三轴身体加速度和三轴陀螺仪；
- 活动类别：6 类。

项目读取六个窗口信号通道：

```text
body_acc_x, body_acc_y, body_acc_z
body_gyro_x, body_gyro_y, body_gyro_z
```

每个通道提取均值、标准差和均方根，共 18 个输入特征。`subject_id` 只用于按受试者划分数据，不作为模型输入。

## 4. 数据清洗与特征处理

### 4.1 缺失值和非有限值

实际运行结果：

| 检查项目 | 结果 |
| --- | ---: |
| 总样本数 | 10,299 |
| 特征数 | 18 |
| 缺失值总数 | 0 |
| 非有限值总数 | 0 |
| 完整重复行 | 0 |
| 特征完全重复行 | 0 |

虽然数据集页面标注没有缺失值，代码仍对每个特征执行了空值、非数值和无穷值检查。

### 4.2 异常值

使用训练集的 Q1-1.5×IQR 和 Q3+1.5×IQR 作为统计异常标记。该标记用于数据分析，不代表这些传感器值一定错误，也不自动删除样本，因为高强度动作可能产生合法的极端值。

实际的统计结果保存在：

```text
data/processed/data_quality.json
```

### 4.3 特征提取

对于每个 128 点窗口，使用以下公式：

```python
mean = np.mean(signal)
std = np.std(signal, ddof=0)
rms = np.sqrt(np.mean(signal ** 2))
```

处理后的数据保存在：

```text
data/processed/features.csv
```

## 5. 数据集划分与防止数据泄漏

保留 UCI 官方训练集和测试集的受试者划分，并将官方训练集的受试者进一步划分为训练集和验证集。

| 数据集 | 样本数 | 受试者数 |
| --- | ---: | ---: |
| 训练集 | 5,551 | 16 |
| 验证集 | 1,801 | 5 |
| 测试集 | 2,947 | 9 |

训练集和验证集使用 `GroupShuffleSplit(random_state=42)` 按 `subject_id` 划分。代码已验证训练、验证和测试受试者集合没有交集。

标准化器只在训练数据中拟合。最终确定模型后，使用训练集和验证集合并数据重新训练，再在测试集上进行一次最终评价。

## 6. 模型训练与比较

比较的模型：

1. 逻辑回归：作为线性基线模型，使用 `StandardScaler`；
2. 随机森林：作为非线性模型，不依赖特征标准化。

验证集结果：

| 模型 | Accuracy | Macro Precision | Macro Recall | Macro F1 |
| --- | ---: | ---: | ---: | ---: |
| Random Forest | 0.7651 | 0.7838 | 0.7596 | 0.7629 |
| Logistic Regression | 0.6591 | 0.6795 | 0.6501 | 0.6480 |

根据验证集宏平均 F1，选择随机森林作为交互原型使用的最终模型。最终模型保存在 `models/final_model.joblib`，由 `python -m src.train` 重新生成。

## 7. 测试集评价与错误分析

### 7.1 总体指标

随机森林在独立测试集上的结果：

| 指标 | 数值 |

| Macro Recall | 0.7977 |

| 测试样本数 | 2,947 |

### 7.2 各类别指标

| 活动 | Precision | Recall | F1 | Support |
| --- | ---: | ---: | ---: | ---: |
| WALKING | 0.7665 | 0.7742 | 0.7703 | 496 |
| WALKING_UPSTAIRS | 0.6917 | 0.7813 | 0.7338 | 471 |
| WALKING_DOWNSTAIRS | 0.8511 | 0.7214 | 0.7809 | 420 |
| SITTING | 0.8286 | 0.7678 | 0.7970 | 491 |
| STANDING | 0.8187 | 0.8571 | 0.8375 | 532 |
| LAYING | 0.8700 | 0.8845 | 0.8772 | 537 |

### 7.3 混淆矩阵

原始数量混淆矩阵如下，行是真实类别，列是预测类别，类别顺序为：

```text
WALKING, WALKING_UPSTAIRS, WALKING_DOWNSTAIRS,
SITTING, STANDING, LAYING
```

```text
[[384, 79, 33,  0,  0,  0],
 [ 83, 368, 20,  0,  0,  0],
 [ 34, 83, 303,  0,  0,  0],
 [  0,  2,  0, 377, 78, 34],
 [  0,  0,  0,  39, 456, 37],
 [  0,  0,  0,  39, 23, 475]]
```

当前结果显示：

- 行走、上楼和下楼之间存在较明显的混淆；
- 坐姿和站姿之间存在较明显的混淆；
- 卧姿的 F1 值最高；
- 上楼的 Precision 相对较低，说明部分其他动态活动被预测为上楼；
- 具体错误样本保存在 `reports/tables/error_cases.csv`。

### 7.4 局限性

- 受试者数量为 30 人，不能代表所有年龄和身体状况的人群；
- 数据采集设备和手机佩戴位置相对固定；
- 活动类别有限，不能覆盖所有真实日常活动；
- 窗口之间存在重叠，样本并非完全独立；
- 18 个统计特征比完整时频特征简单，可能损失部分识别信息；
- 模型概率没有自动解释为校准后的真实置信度；
- 预测结果不能代表医学诊断或健康状况判断。

## 8. 交互原型设计

启动命令：

```powershell
streamlit run app.py
```

原型支持：

- 选择六类活动演示样例；
- 上传一行或多行 18 特征 CSV；
- 下载输入模板；
- 编辑模型输入；
- 检查缺失列、空值、非数值和无穷值；
- 检查输入是否超出训练数据范围；
- 展示预测活动和各类别模型估计概率；
- 展示全局特征重要性及特征含义；
- 修改输入后重新预测；
- 对比修改前后的预测结果；
- 显示数据来源、适用范围和非医疗声明。

训练范围之外的数值会产生提示而不是自动删除，因为范围外输入可能是合法但训练数据没有充分覆盖的传感器情况。

## 10. 改进建议

用户测试完成后，至少提出三条建议，并标注问题属于模型、数据或界面。可从以下方向结合真实反馈选择：

1. **界面**：将 18 个特征进一步按传感器分组，减少用户输入负担；
2. **数据**：补充不同手机放置位置、更多用户和活动切换窗口；
3. **模型**：加入更多时域/频域特征，并进一步评估概率校准；
4. **界面**：强化训练范围外输入和低确定性结果的视觉提示。
